# Design System — Hermes Relay

> **配色：只有一套「暖纸」**（米白棉纸 + 赭石印泥）。2026-10-09 起深色 / 冷纸两套删除，
> 此后这个项目的界面一律用暖纸配色，不再提供切换（`data-theme` 机制已移除）。

> **版式**：侧栏与设置页按 C 号样张（高密度）落地 —— 侧栏 272px、行高 32px、分组吸顶。
> （当时的对照样张没有随这份源码发布，以本文件的数值为准。）
>

> - 风格与令牌：`ui-ux-pro-max` 风格库

## 排版

**2026-10-09 起整站一套无衬线（方案 A），三套字体全部自托管 —— 来源、体积、切块与重新生成见 `FONTS.md`。**

- 拉丁：`Source Sans 3`（400/600，`web/fonts/`，next/font/local 加载，自带度量对齐的兜底字体）
- 中文：`Noto Sans SC` 思源黑体（400/600，按 unicode-range 切 101 片/字重，浏览器按需下片）
- 等宽（代码、时间、耗时、工具行、数字）：`Sarasa Mono SC` 等距更纱黑体（400/700；中文正好占 2 个英文字符宽，表格 / ASCII 图 / 注释能对齐），数字一律 `tabular-nums`
- 外壳（侧栏、按钮、标签、表头）/ 正文 / 标题 / 品牌用的是同一套：`--font-ui` = `--font-read` = `--font-title` = `--font-sans`
- 代码块：行内 13.5px、块内 14px（比换字体前各加 0.5px，更纱黑体的拉丁偏窄），关掉连字 `font-variant-ligatures: none`
- 正文 16.5px / 行高 1.72，阅读宽度 `--container-read` = 848px（**值是容器宽，正文文字实际 768px**；用户 2026-10-09 定稿的口径）；**消息列与输入框共用同一个令牌**；段距 20px
- **宽度只有一个来源**：`--container-read`。`.prose-relay` 自身**不要**再写 `max-width`（曾有一条 `68ch`：
  那是英文口径，中文只够约 34 字一行，把外层已经放宽的正文又压了回去）
- 消息流上下各留 28px 渐隐带（`.msg-stream` 的 `mask-image`）：内容滚到标题区 / 输入区旁边时淡出，不是硬切。渐隐装在滚动容器上，别挪到内层宽度容器（会跟着内容列一起收窄）
- 侧栏：会话行 12.5px、分组标题 11px、时间 11px 等宽
- 字体文件不进 git（SIL OFL，脚本生成）；`/fonts/` 在 nginx 上一年 immutable 缓存

## 形状与动效

- 圆角：正文区的卡片 / 控件沿用 4px / 3px 令牌；**侧栏与设置页按 C 样张放大到 6–9px**；**输入框 20px**（2026-10-09 起为胶囊级，刻意比全站大得多，规则见下表）。**输入框内部的按钮一律收成圆**：图标键用正圆、文字键（插话 / 停止）用胶囊 —— 大圆角容器里留直角按钮是明确要避免的混搭
  （弹窗外框 9px、按钮与行 6–8px）。这两处是刻意的不一致，如需全站统一再说。
- 纸上的两份物理感：`.paper-lift`（抬起来的一层）、`.paper-press`（压下去的凹槽）——
  由 `--shadow-card` / `--shadow-in` 定义，阴影带纸色而不是纯黑
- 纤维层：`body::after` 一层灰度噪声（`--fiber`，opacity 0.16），破掉纯平面的数字感
- 过渡 160–200ms，只动 `background` / `border-color` / `color` / `opacity` / `transform`
- 唯一常驻动效：生成末尾的闪烁光标；`prefers-reduced-motion` 下全部关闭

## 组件约定

| 组件 | 形态 |
| --- | --- |
| 侧栏 | 宽 **272px**。顶部品牌行（赭石方块 R + 无衬线名）；实心赭石「新对话」34px；搜索框 32px；日期分组标题滚动时吸顶（11px）；会话行 32px，选中为整行淡赭底 + 左侧 1px 强调线；底部只有设置入口（会话计数那一行已去掉） |
| 设置弹层 | 1040×660、圆角 9px。左栏 206px：**只有菜单，没有搜索/过滤框**（2026-10-09 用户要求去掉）。**菜单行规格只有一份**：31px 高、`px-2`、12.5px、行首 14px 图标位（分组标题放箭头、单项放图标）；一级菜单可展开收起、**默认全部收起**；分组只有一项时不设二级菜单，该项直接当一级菜单（现为「外观」）；二级行 `pl-[22px]`（比一级缩进 14px）表达层级，不靠字号；一级分组标题字重 500，其余 400；选中项所在分组自动展开。结构写在一处配置 `NAV_GROUPS` 里。右栏三种状态——空状态（入口列表）、文件（顶部标题/路径/计数 + 衬线正文 + 底部保存条）、外观（只有一张暖纸卡，标「当前」） |
| 助手消息 | 不套卡片，直接排在纸面上。无衬线正文，文字宽 768px（容器 `--container-read` 848px，左右各留 40px） |
| 用户消息 | 右侧气泡，`--color-raised` 底，无边框 |
| 工具调用 | 等宽小字一行一个，前缀小圆点；跑完的点变暗 |
| 思考片段 | 左侧 1px 发丝线 + 弱化标签；生成时展开，历史里折进 `<details>` |
| 耗时 | 回答下方等宽小字「用时 X.X 秒」，行首一个 **24×24 的复制图标**（无文字，悬停提示「复制这条回复」，复制的是正文，不含思考和工具）。代码块、文件预览里另有自己的复制 |
| 代码块 | `--color-panel` 底 + 发丝描边，右上角复制按钮，左上角语言标签，浅色高亮 |
| 输入区 | **浮起胶囊**（2026-10-09 方案 B 起步，同日晚按用户给的参考图调整）：底色 `--color-input`（#fffdf8，比纸面更白一档）、**圆角 20px**、常态就带一圈柔和外阴影（`--shadow-input`），**不画任何描边**。**宽度不由它自己定**：外层（`composer.tsx`）和消息列用同一套 `max-w-read + px-10`，输入框填满 —— 卡片外缘压在正文文字边缘上（之前它自己 `max-width` + 居中，在 1440px 屏上比正文宽出 35/45px）。框内左侧是**正圆**的加号键（36px、`bg-raised` 底），右侧「插话 / 停止」是胶囊键。**强调态 = 聚焦时，或框里已有内容时**（`:has(textarea:not(:placeholder-shown))`，打完字点走不会缩回空态）：只把影子抬高一档（`--shadow-input-on`），底色和形状都不变。阴影一律用墨色 `rgba(45,45,42,·)` 染色，不用纯黑。所有控件 36px 高、图标 18px，发送键是 36px 圆形图标键。textarea：placeholder **与正文同为 16px**（字号不同就不可能同时居中），内边距不对称 `pt-[7px] pb-[3px]`，把中文墨迹拉到正中（实测偏移 0.00px）。支持 Ctrl+V 贴图。**输入框上方不再留空**（2026-10-13 起 `pt-0`）：消息区底边与输入框卡片顶边**零间距**，正文由 `.msg-stream` 的 28px 渐隐直接过渡到输入框上边缘（用户原话「输入框上面就是正文的文字遮挡阴影」；他之前把这段 16px 空白叫「空的状态条」，注意别跟 `StatusBar` 搞混） |
| 输入框下面那一行 | 2026-10-13 起：**左边「缓存命中 98%」（有压缩时后面再跟压缩提示）、右边「模型 · 档位」**（`composer.tsx` 的 meta 行，`mt-2 px-2`、12.5px、等宽数字）。**输入框上方原来那条状态条已整个删掉**（用户要求），里面的缓存命中与压缩提示都落到这一行。右侧是 `model-picker.tsx`：触发按钮是**无边框无底色**的纯文字（悬停才变深）；主面板 **288px、圆角 9px、向上展开**（`bottom: calc(100% + 10px)`，底色 `--color-input`、边框 `line-strong`、三层阴影 `0 0 0 1px rgba(45,45,42,.05)` + `0 4px 10px rgba(45,45,42,.10)` + `0 24px 56px -16px rgba(45,45,42,.38)`）：先是模型列表（名称 13px + 渠道 11.5px 等宽小字两行 + 勾选），下面两行入口「思考强度 · 当前档」「添加模型」。**「思考强度」不切换主面板，而是从左侧再弹一个 152px 的小框**（定位 `right-[294px]` = 主面板宽 288 + 6px 缝，只装五档，悬停即开、鼠标移开 180ms 收；主面板内容保持不动）；「添加模型」是表单（显示名称 / 接口地址 / 密钥 / 模型 ID + 测试 + 保存）。五档对应 `none/low/medium/high/max` |
| 思考 / 工具行 | 12.5px、`leading-[1.4]`（=17.5px 行高），块间距 `mb-0.5`（2px）；工具行再 `pl-6` 缩进 24px。一整条链 2026-10-09 从 24.1px/行收紧到 17.5–19.5px/行。**行与行之间一律 2px**。与正文的间距（2026-10-13 定稿，方向：一串过程行属于它**上面**那段正文）：**正文块 → 过程行 4px（贴着上文）**、**过程行 → 正文块 14px（与下面那段拉开）**。实现**不在正文那侧用负补偿** —— 正文段下边距是 20px（p / ul / ol）、表格与引用 24px、流式尾巴那段被 stream-tail 规则清零是 0，用「减一个固定值」会算出三种结果甚至负值（实测 −12px，正文和工具行压在一起）；现在先把该块最后一段的下边距清零，再由正文块自己给 `margin-bottom`。反面教材：给每一行都设正负补偿会让行间折叠成负值（互相重叠），整块忽紧忽松 |
| 折叠块展开态 | **链标题行 → 展开内容 2px**、链内行间 2px、**链尾 → 下面正文 14px**（收起态也保持 14px：标题行自己的 2px 不会与 fold-body 的 margin 折叠，所以收起态写 12px）；**思考 / 工具详情卡片距摘要行 4px**（原 6 / 8px）。「与下文拉开」的 margin 必须写在 `.fold-body` 上 —— 写在标题行上时，展开后这 14px 会落在标题和自己的内容之间（2026-10-13 用户反馈「展开后反而看起来更远」）。详情卡片上边距在 `messages.tsx` 里（`mt-1`），不在 CSS |

## 禁止（来自 craft-floor，别违反）

- 彩色 >1px 的左边条（只用 1px 中性线）
- 发丝边框 + 大范围阴影同时出现
- 等宽字体当"技术感"装饰（只用于代码、时间、数字）
- Inter（被判定为用烂的默认字体）
- 正文小于 14px、正文对比低于 4.5:1
- emoji 当图标（用 Phosphor / Lucide）
- 渐变文字、装饰性玻璃模糊
- **重新引入 `data-theme` 配色切换**（现在只有一套暖纸）

## 浏览器表面

选区色、光标色、滚动条、焦点环、链接下划线偏移、数字等宽对齐——全部按上面令牌上色，别留浏览器默认。
`color-scheme` 固定 `light`（原生控件、滚动条按浅色渲染）。
